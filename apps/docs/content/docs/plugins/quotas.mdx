If you sell data rooms, storage is part of the plan: the starter tier gets 10 GB, a large deal gets more. Without
limits, one room that receives a scanned archive of every contract the target ever signed fills your bucket and your
bill. Administrators also want to see how full a room is before a counterparty starts a large upload.

The quotas plugin counts what each room and each tenant stores, and refuses uploads that would go over a limit
**before any bytes move**. Limits come from a default for every room, a room's own limits set by a tenant
administrator, and a per-tenant function you connect to your billing plan.

```ts
import { betterFiles } from 'better-files';
import { betterFilesIamPlugin } from 'better-files/iam';
import { quotasPlugin } from 'better-files/plugin-quotas';

const plugins = [
  quotasPlugin({
    room: { maxBytes: 50 * 1024 ** 3, maxFileBytes: 2 * 1024 ** 3 }, // default for every room
    tenant: async (tenantId) => plans.limitsFor(tenantId), // from your billing plan
  }),
] as const;
const iamPlugin = betterFilesIamPlugin({ plugins }); // registers better-files:quotas:manage

export const dr = betterFiles({ /* iam, database, storage, secret */ plugins });

const usage = await dr.api.quotas.room(credential, { tenantId, roomId });
// { bytes, documents, versions, limits: { maxBytes, maxFileBytes }, ratio: { bytes: 0.42 } }
```

The plugin owns two tables, `quotaUsage` and `quotaLimits`. On a SQL database, run `better-files generate` and
`better-files migrate` after adding it.

## How uploads are checked

When an upload session is created, the plugin's `beforeUpload` hook checks, in this order:

1. The file size against the smaller of the room's and the tenant's `maxFileBytes`.
2. The room's usage plus this file against the room's `maxBytes` and `maxDocuments`.
3. The tenant's usage plus this file against the tenant's `maxBytes` and `maxDocuments`.

A new version adds bytes but not a document. The first refusal throws `QUOTA_EXCEEDED` (HTTP 429) with `details.scope`
set to `file`, `room` or `tenant`, and publishes `quota.exceeded` at once (even though the request fails).

```ts
import { BetterFilesClientError } from 'better-files/client';

try {
  await files.upload({ parentId: folder.id, file });
} catch (error) {
  if (error instanceof BetterFilesClientError && error.code === 'QUOTA_EXCEEDED')
    showUpgradeDialog(error.details); // { scope: 'room', limits }
  else throw error;
}
```

A room's effective limits are the `room` option overlaid with the room's own limits. The tenant limits apply on top,
so a room cannot go past its tenant's total.

## Counting

Usage moves when a version is stored, in the same transaction: its bytes, one version, and one document when it is a
document's first version. Every version counts, files generated by other plugins included.

Deleting does not give space back at once: items in the trash still count. `dr.maintain()` recounts the rooms that
were counted longest ago (`recountPerRun` per run) from the stored versions, and recomputes the tenant total as the
sum of its rooms. When the room no longer exists, `dr.maintain()` removes its usage and its limits instead. An
administrator can also recount one room right away with `recount`.

## Endpoints

The `quotas` group: `dr.api.quotas.<name>(credential, input)` on the server and `client.quotas.<name>(input)` on the
[typed client](/docs/frameworks/client). Every input also takes `tenantId`.

| Endpoint | Input | Permission | Returns |
| --- | --- | --- | --- |
| `room` | `roomId` | `better-files:rooms:read` on the room (any member) | The room's usage report. |
| `tenant` | (nothing else) | `better-files:quotas:manage` on the tenant | The tenant's usage report. |
| `setRoom` | `roomId`, `maxBytes?`, `maxDocuments?`, `maxFileBytes?` | `better-files:quotas:manage` on the tenant | The room's report with the new limits. |
| `recount` | `roomId` | `better-files:quotas:manage` on the tenant | The room's report after recounting. |

A usage report is `{ bytes, documents, versions, limits, ratio }`. `ratio` has `bytes` and `documents` (used divided by
the limit) for the limits that are set.

In `setRoom`, a limit is a whole number of at least 0; `null` clears it, so the room falls back to the `room`
default; a limit you leave out is unchanged.

```ts
await dr.api.quotas.setRoom(credential, { tenantId, roomId, maxBytes: 200 * 1024 ** 3, maxFileBytes: null });
```

## Permissions

`room` is open to anyone who can read the room. The other three are authorized on the tenant, not the room, so room
owners and administrators cannot raise their own limits. The plugin grants `better-files:quotas:manage` to no room
relation: give it to your tenant administrators in a [Better IAM](/docs/guides/better-iam) policy, and pass the
plugin to `betterFilesIamPlugin({ plugins })` so Better IAM knows the action.

## Events and activity

| Name | Kind | Data |
| --- | --- | --- |
| `quota.exceeded` | event | `roomId`, `scope` (`file`, `room` or `tenant`), and `limit` and `size` for files or `limits` otherwise |
| `quota.warning` | event | `scope` (`room` or `tenant`), `roomId`, `kind` (`bytes` or `documents`), `used`, `limit` |
| `quota.changed` | activity | The limits `setRoom` changed |

`quota.warning` is published when an upload takes usage from below `warnAt` of a limit to at or above it. Hook it to
[notifications](/docs/plugins/notifications) or [webhooks](/docs/plugins/webhooks) to tell a customer before they
hit the wall.

## Metering in Better IAM billing

`betterIamMetering(iam, options)`, from the same package, is a second plugin (id `metering`). It records Better Files
usage in Better IAM billing and can enforce Better IAM budgets and quota plans. It calls the instance's trusted
`iam.billing` and `iam.quotas` runtimes, so it needs no credential. It needs better-iam 0.2 or later.

```ts
import { betterIamMetering, meteringMeters } from 'better-files/plugin-quotas';

// Once, as the platform: create the meters, then price them on your rate card.
for (const meter of meteringMeters())
  await iam.api.billing.createMeter(rootCredential, { tenantId: rootTenantId, ...meter });

const plugins = [
  quotasPlugin({ room: { maxBytes: 50 * 1024 ** 3 } }),
  betterIamMetering(iam, {
    enforceBudgets: true, // refuse work once an enforced budget is spent
    quotas: { download: 'better-files.downloads' }, // per-person quota plans you define in Better IAM
  }),
] as const;
```

| Meter (key in `defaultMeters`) | Default Better IAM key | Aggregation and unit | Recorded on |
| --- | --- | --- | --- |
| `uploadBytes` | `better-files.upload-bytes` | sum, byte | `document.uploaded`, `version.created` |
| `downloadBytes` | `better-files.download-bytes` | sum, byte | `document.downloaded` |
| `downloads` | `better-files.downloads` | sum, file | `document.downloaded`, `folder.downloaded` (per file) |
| `views` | `better-files.views` | sum, view | `document.viewed` |
| `rooms` | `better-files.rooms` | sum, room | `room.created` |
| `participants` | `better-files.participants` | unique, participant | downloads and views |

`meteringMeters(meters?)` returns these as definitions for `billing.createMeter`, with your renamed keys, and without
the ones you turned off.

How it behaves:

- **When usage is recorded.** From published events, after the change commits, with the event id in the idempotency
  key. Refused or rolled-back actions are never billed, and a redelivered event is billed once.
- **Who is billed.** The acting person, and nobody for system actions. When Better IAM does not know the actor (a
  share-link visitor, for example), the usage is recorded for the tenant without a person, and `participants` is
  skipped.
- **Budgets.** With `enforceBudgets`, a spent budget refuses the action with `QUOTA_EXCEEDED`,
  `details: { scope: 'budget', budget }`, and publishes `quota.exceeded`.
- **Quota plans.** Each meter in `quotas` is consumed per person. A refusal is `RATE_LIMITED` with
  `details: { scope: 'quota', meter, plan, reason, retryAfterMs }`. People no plan covers are unlimited. A folder
  ZIP is checked once per file.

## Errors

| Code | When |
| --- | --- |
| `QUOTA_EXCEEDED` (429) | An upload would exceed a file, room or tenant limit, or an enforced Better IAM budget is spent. |
| `RATE_LIMITED` (429) | A Better IAM quota plan refused the action, or a check failed with `onCheckError: 'closed'`. |
| `FORBIDDEN` (403) | `tenant`, `setRoom` or `recount` without `better-files:quotas:manage` on the tenant. |
| `NOT_FOUND` (404) | The room does not exist in the tenant. |

## Limits

- Limits are soft under concurrency: two uploads checked at the same moment can both pass, and together go over.
- Storage counts every version and the trash until it is purged; it can lag after purges until the next recount.
- There is no limit on the number of versions, only on their bytes.
