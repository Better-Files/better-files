A data room is a place where one party shares confidential documents with others, with control over who sees what,
what they may do with it, and a record of what they did. Better Files gives your app that place as a library. These
pages explain the model it is built on, one idea at a time.

Every call follows the same shape: a credential, the tenant, and the input.

```ts
const room = await dr.api.rooms.create(credential, { tenantId, name: 'Project Falcon' });
const folder = await dr.api.folders.create(credential, {
  tenantId,
  parentId: room.rootNodeId,
  name: 'Financials',
});
```

## Vocabulary

| Term | Meaning |
| --- | --- |
| Tenant | One organization in your app. Every record carries a `tenantId`; an id from another tenant is simply not found. |
| Room | A data room: a tree of folders and documents, its people, its settings and its status (`draft`, `live`, `closed`, `archived`). |
| Node | One item in a room's tree: a folder or a document. Permissions, activity and moves all work on nodes. |
| Folder | A node that holds other nodes. Each room has one root folder, `rootNodeId`, named `Index`. |
| Document | A node that holds a file. Its content lives in versions. |
| Version | One upload of a document's content, numbered from 1. One version is current; older ones stay available to editors. |
| Member | A row on the room's roster: a person who was invited, joined, or was suspended, removed or expired. |
| Permission group | A named set of members in one room, such as "Buyers". It is a Better IAM group under the hood. |
| Relation | A person's or group's role on the room in Better IAM: `owner`, `admin`, `publisher`, `editor`, `contributor`, `viewer` or `auditor`. It decides which actions they may perform. |
| Capability | One thing a subject may do with a node: `LIST`, `VIEW`, `PRINT`, `COPY_TEXT`, `DOWNLOAD_WATERMARKED`, `DOWNLOAD_ORIGINAL`, `UPLOAD`, `EDIT`, `DELETE` or `MANAGE`. |
| Preset | A named set of capabilities, such as `view` or `download`, so you rarely list capabilities by hand. |
| Entry | One cell of the permission matrix: a subject (a person, a group or a share link), a node, and the capabilities granted there. |
| Ticket | A short-lived signed token for one file transfer: a download, a viewer page, or a ZIP. |
| Activity record | One line of a room's activity log: who did what, to which node, when. Records are hash-chained, so edits are detectable. |
| Plugin | A package that adds tables, endpoints, capabilities and hooks, such as NDA gating or watermarking. |

## How access is decided

Each operation passes two checks, and either can refuse it:

1. **The permission matrix (layer A)**, kept by Better Files: which capabilities a person holds on a folder or
   document, from entries on that node and its ancestors.
2. **A Better IAM decision (layer B)**: whether the person may perform the operation's action, such as
   `better-files:documents:download`, which follows from their relation on the room and your own policies.

[Permissions](/docs/guides/concepts/permissions) explains both layers in detail.
