# Better Files documentation site

Next.js 16 + [Fumadocs](https://fumadocs.dev) 16, modeled on Better IAM's docs. Content lives in `content/docs`,
reference pages are generated from the repository, and the home page runs the real permission resolver from
`@better-files/core` in the browser. The site also has section-filtered search, Mermaid diagrams, social cards, and
LLM-friendly Markdown endpoints (`/llms.txt`, `/llms-full.txt`, `/llms.mdx/docs/...`).

```sh
pnpm --filter @better-files/docs generate   # after `pnpm build`: package data, stats and the generated reference pages
pnpm --filter @better-files/docs dev        # http://localhost:4100
node apps/docs/scripts/check-content.mjs    # MDX syntax, components, frontmatter, links and #anchors
pnpm --filter @better-files/docs build
```

The home page imports `@better-files/core`, so build the workspace packages (`pnpm build`) before building the site.

## Layout

| Path                                                                                  | What it is                                                                   |
| ------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `content/docs/{guides,frameworks,plugins,operations,reference}`                       | The five sidebar sections; each folder's `meta.json` orders its pages        |
| `content/docs/reference/{operations,actions,capabilities,errors}.mdx`, `changelog.md` | Generated by `scripts/generate.mjs`; edit the script, not the pages          |
| `generated/`                                                                          | Package list and stats from the workspace manifests (`scripts/generate.mjs`) |
| `app/(home)`                                                                          | The home page; `components/home` holds its sections and visuals              |
| `components/mdx.tsx`                                                                  | The MDX components available on every page without imports                   |
| `lib/icons.ts`                                                                        | Icon names for frontmatter, `meta.json` and `Card icon="…"`                  |
| `components/base`                                                                     | BoardUI components, kept in upstream formatting (excluded from Prettier)     |

## Writing pages

Frontmatter: `title` and a one-sentence `description` (at most 160 characters) are required; `metaTitle`, `icon`,
`status` (`new`, `beta`, `experimental`, `deprecated`), `packages` and `sources` are optional. Pages are written
from the source: every API, option and error a page names must exist in `packages/*/src`.

Run `node apps/docs/scripts/check-content.mjs [section/page]` before building. It compiles every page as MDX, checks
that JSX components are registered or imported, checks frontmatter, and checks that `/docs/...` links and `#anchors`
exist.

## Deploying on Railway

The repository root has a `railway.json` that builds this site with `apps/docs/Dockerfile`: create a Railway service
from the GitHub repository and it deploys on every push that touches the site or the packages (`watchPatterns`).
The image installs and builds the whole workspace, then builds the site and runs `next start` on Railway's `$PORT`;
the health check is `/`.

Railway passes its `RAILWAY_PUBLIC_DOMAIN` to the build, so canonical URLs, the sitemap and `llms.txt` use the
service's domain. For a custom domain, set `DOCS_SITE_URL` (for example `https://better-files.dev`) as a service
variable; it is baked in at build time, so redeploy after changing it.

```sh
docker build -f apps/docs/Dockerfile -t better-files-docs .   # the same image locally
docker run -p 3000:3000 better-files-docs
```

## Configuration

| Variable                                                                                   | Default                                                        | Purpose                                                   |
| ------------------------------------------------------------------------------------------ | -------------------------------------------------------------- | --------------------------------------------------------- |
| `DOCS_SITE_URL`                                                                            | `https://$RAILWAY_PUBLIC_DOMAIN`, else `http://localhost:4000` | Canonical origin for metadata, the sitemap and `llms.txt` |
| `NEXT_PUBLIC_DOCS_REPOSITORY_URL`                                                          | `https://github.com/Better-Files/better-files`                 | GitHub button, "Edit this page", source and issue links   |
| `NEXT_PUBLIC_DOCS_REPOSITORY_BRANCH`                                                       | `main`                                                         | Branch for source and edit links                          |
| `DOCS_X_HANDLE`                                                                            | none                                                           | `twitter:site` on social cards                            |
| `DOCS_GOOGLE_SITE_VERIFICATION`, `DOCS_BING_SITE_VERIFICATION`, `DOCS_YANDEX_VERIFICATION` | none                                                           | Search console verification tags                          |

## Dependency note

The workspace pins `mdast-util-to-markdown` to 2.1.2 (`pnpm-workspace.yaml` overrides). Version 2.2.0 makes Fumadocs
16.15's processed-Markdown stringifier recurse forever on bold text, which fails the build with "Maximum call stack
size exceeded" on nearly every page.
